# 我的嫁妆，谁也别想拿去飞升｜无人值守分镜制作（豆包工作任务版）

## 创建时的配置

**技能名称**：`修仙小说无人值守分镜制作`  
**适用场景**：用户给出一至两章原文，要求生成分镜提示词、生产剧本、资产、Seedance 视频或整章制作。  
**运行模式**：工作任务 → 云电脑。  
**模型**：豆包 2.1 Turbo 高。  
**需要启用的能力**：`操作浏览器`、本地文件读取与写入、文件上传和下载。没有这些能力时，只完成可验证的文本和文件工作，不假装已经上传、生成或下载。

此 skill 是完整制作编排器，不是提示词润色器。它必须先建立可恢复的章节包和资产台账，再逐镜制作；不得跳过状态核验、尾帧、下载或质检。

## 0. 总原则

1. 只处理用户点名的一至两章，章节和镜头都顺序执行。
2. 原文、已确认角色设定、已验收素材和上一镜尾帧是事实来源；不得为好看改变阵营、身份、境界、道具归属、胜负、空间逻辑或剧情结果。
3. 浏览器超时、上传中断、下载中断均为“未知结果”。先检查可见页面和本地文件，再决定是否继续；未知状态绝不盲重传、重投、重复下载或切换账号。
4. 已授权连续生产时，除验证码、登录、付费、模型不可用、网页规则实质改变或无法消除的硬校验错误外，持续完成流程，不把普通慢速或单次超时交给用户。
5. 不删除、不覆盖用户原有或验收文件。重制使用 `-重制-v2`、`-重制-v3`；保留原片和版本。
6. 浏览器最多两个标签：一个生产标签、最多一个恢复标签。关闭失效、空白、重复或完成标签；至少留一个普通标签；开第三个前先关确认无用的标签。

导演分镜生成的默认账号是**`用户867998`**。用户在本次任务明确指定其他账号时，以该指定账号为准；无指定则使用 `用户867998`。无论采用哪个账号，都必须由页面可见账号标签精确验证，且该账号必须实际提供 `Cinematic Storyboard Prompt Generator`。

每次导演阶段依次核验：

1. 可见账号标签 = 本次用户指定账号；未指定时 = `用户867998`；
2. 模式 = `工作任务`；
3. 环境 = `云电脑`；
4. 模型 = `豆包 2.1 Turbo 高`；
5. 技能 = `Cinematic Storyboard Prompt Generator`。

账号不同、未知、未加载或没有目标技能时，禁止使用同名替代技能、上传、粘贴原文或发送。先在已授权的普通 Chrome 网页豆包会话内切换到本次解析的目标账号，重新读取可见标签；无指定时目标账号就是 `用户867998`。

浏览器控制只使用工作任务的 `操作浏览器` 能力和可见网页控件：读取标签、打开页面、点击、输入、上传、等待、下载和检查可见结果。不得通过隐藏输入框、开发者工具、Cookie、密码、会话储存、脚本注入或猜 URL 绕过界面。

## 2. 章节判型与资产复用

完整阅读原文，标为 `文戏`、`打戏` 或 `混合叙事`。在章节 `资产/10-资产复用台账.md` 记录：章节类型及理由、已有角色、道具、场景、精确路径、可见状态（服装/境界/伤势/激活）、拟用镜头。视觉状态真正匹配才可复用；服装、境界、投影、伤势、激活或损坏不同则标为缺失状态资产。

声音硬锁：

- 沈青梧：清冷女中音，沉静清透、咬字利落、气息稳定；
- 咪咪：正太奶凶奶音，软糯少年感，1.05倍；无台词也标注保持连续性；
- 青鸾：冷静稚嫩女音，清亮不尖锐，克制的幼龄灵兽感；
- 其他说话角色：根据身份、年龄、剧情情绪建立稳定声线，后续复用。

## 3. 导演分镜、剧本与文件包

仅上传本章真正需要且已验收的角色/道具参考图；一次上传、顺序固定，并先写：

```text
@image1 = [角色/道具名称]
@image2 = [角色/道具名称]
```

随后提供章节号、标题、完整原文、章节类型、`修仙版`、`旁白模式B`、`打戏段无BGM，文戏段可加BGM`。

默认 **9–10镜、每镜10秒**。只有完整台词、必要因果、空间转场或签名场面确实装不下时，才扩到11–13镜。新增镜头必须拥有不同戏剧任务和不可逆终态。相邻镜只可用0–1秒承接尾帧；不得完整重复揭示、命令、蓄力、攻击、命中、倒地或反应。

先建立内部进展表：`前镜终态 → 本镜新动作 → 本镜终态 → 下镜所需动作`。若两镜主动作与后果相同，合并或重写后镜。

输出必须是一份 Markdown 制作文件，不是摘要。每镜使用：

```text
## S01｜00:00—00:10｜[镜头标题]
【上一镜尾帧衔接】[无尾帧或精确前镜终态]
①画质基准：[16:9、10秒、东方修仙3D动漫电影质感]
②角色・场景・核心设定：[@image映射、境界/服装、站位、朝向、道具、场景]
③时间轴：[0.0–2.0；2.0–6.0；6.0–10.0 的连续因果]
④声音：[旁白、完整台词、声线、口型、音效、BGM]
⑤连续性与终态：[本镜新终态及下镜继承项]
⑥负面提示词：[无字幕、无水印、无穿模、无重复动作及专属禁止项]
```

台词不得删尾。10秒常速不够时用清晰的1.10–1.50倍语速；仍放不下则拆镜。

保存导演稿为 `<章节>/资产/07-seedance-2-fast-prompts.md`。结构验收通过后，该文件每个 SG 的视频提示词正文是唯一且不可本地修改的生产原稿；不得再以旧提示词或其他规则扩写、缩写、重组或替换。仅据原文与导演稿生成：

- `02-screenplay.md`：含角色境界与战力状态表、场景、完整台词、镜头目标、进出状态；
- `03-assets.md`：缺失资产与状态；
- `04-gpt-image-2-prompts.md`：仅缺失资产的生图提示词；
- `05-storyboard-video-prompts.md`：如保留，仅能逐 SG 原样镜像 `07` 正文，不得成为第二套视频提示词；
- `06-qc.md`：逐镜验收表。

## 4. 文戏、打戏、法术与特效

文戏使用动机明确的建立、轻推近、轻拉远、侧跟、反打、揭示和反应停留；先保证口型、声线、眼神和信息对象。不要给普通对话强加法术、强特效或无意义绕圈。

中型及以上冲突、法术、阵法、法相、群战、灾变、收尾技必须明确：

1. 左/中/右与前/中/后景、阵营、朝向、武器/法术方向；
2. 每人独立移动线、时间差、落点与反应，禁止共享落点或穿过彼此；
3. 起势 → 推进 → 接触 → 后果，接触不能被白闪、浓烟或泛光遮掉；
4. 主光、体积层次、符纹/粒子/能量材质、环境受力、碎石/尘浪/裂缝、余波；
5. 受击反馈、镜头响应和精确终态。

大招要有五层可辨视觉结构：主体法相/器物、符纹或阵法、实体能量/投射物、环境受力、光影余波。特效必须来自已写明的施法者、法器或阵眼。

护盾、结界、火墙、阵壁、救援镜先固定：

`友方区 | 护盾接触面 | 敌方区`

施法者、受护者、同盟始终同侧；敌人与来袭物只在另一侧。阵营颠倒、投射物生在友方区或友军互为敌人均为整镜失败。

剑雨、器雨、鼎雨、法相、群体坠击等签名场面，必须先呈现可辨源头与生成机制，再有前中后三层实体群、分批可读命中、环境后果和主器/主角收束。普通泛光、单一爆炸、无源投射物或单颗陨石不能冒充。

## 5. 缺失资产

仅在导演稿和资产台账都确认缺失时生图。角色必须同页前、左、后、右四视图，身份、脸型、服装、比例、武器、轮廓一致；场景无角色、字幕、水印；道具展示材质、结构和比例。不同人类角色使用独立生图会话。新状态以已验收母版为参照。逐项验收身份、四视图、肢体、服装状态、文字/水印、与已有角色相似度；失败版本放拒绝区，绝不替换验收资产。

每次生成或视频提交前重新检查 SG 图片顺序、路径、状态和绑定；缺失、待生成或不匹配即禁止提交。

## 6. Seedance 视频生成

网页版豆包逐 SG 执行：

1. `生成视频` → `Seedance 2.0 Fast` → `16:9` → `10秒`；每次切换账号后重新核验；
2. 只用可见 `+` → 上传文件或图片，一次文件选择器按 manifest 顺序上传；立即核对缩略图数量与顺序；
3. 视频提示词前写完整 `@imageN = 角色/道具/场景` 图例；尾帧直续则首行写 `@image1 = S[上一镜编号]尾帧`；
4. 完整原样粘贴 SG 导演提示词，不删改站位、时间轴、声音、特效、环境后果或负面提示词；除图片图例和尾帧标记外不得增加任何旧规则、外部规则或本地改写；
5. 只认官方“视频生成已提交”且模型为 Seedance 2.0 Fast；
6. 7–8分钟无结果且无失败时，仅刷新同一会话一次检查已有任务，刷新不是重投。

普通素材安全确认按已授权自动确认。验证码、登录、付费、模型不可用或上传规则改变时停在边界。默认先使用第3步的 `director_account` 生成视频；只在官方“视频生成已提交”出现后计一次额度。同一账号累计3次官方提交，或页面更早明确显示额度耗尽后，当前任务完成回传、下载和状态确认，再切换下一个账号继续下一镜。切号后重新核验 `Seedance 2.0 Fast`、`16:9`、`10秒`，视频提示词正文仍原样使用已验收 `07`。其余普通账号优先，之后才用 `yindu-1`、`yindu-2`、`fei-1`；`fei-1`在剩余账号中最后。用户明确指定保留账号做第3步时，该账号作为本次初始视频账号是唯一例外。全部用量写入台账。

## 7. 下载、尾帧、质检、重制

回传后只下载无水印资源面板中本任务最上方“视频1”，保存 `<章节>/镜头/<章节号>-<镜头号>.mp4`。确认视频可读及时长正确。下一镜尾帧直续则抽取 `<章节>/镜头/<章节号>-<镜头号>-尾帧.png`。

逐镜抽帧验收：身份/服装/境界/道具/声音连续；台词、口型、反应完整；站位、行动线、阵营、武器方向正确；接触与后果可读；护盾分区、法相/器雨来源、实体投射物、环境受力和落点可读；无字幕、水印、穿模、消失、重复或空间跳变；尾帧可供下一镜承接。

严重缺陷重制并保留原片。每次都使用已验收 `07` 中该 SG 的完整原始正文和相同图片图例重做整镜，保存为 `重制-vN`；不得另写局部桥接提示词、改写全镜提示词或覆盖旧版本。

## 8. 浏览器恢复

当能列出标签但不能读取、点击、上传或截图：

1. 记录最后成功页面、标签、任务状态，保留文件和标签；
2. 两秒后只建立一次新控制连接，只做一次轻量标签检查；
3. 每次探测只做一个操作：接管标签、读标题/URL、读页面、点击、上传分别执行；
4. 旧标签接管失败不反复接管，使用一个恢复标签，先验证可读标题/URL再导航；
5. 恢复标签也不可靠时只开一个同配置恢复窗口，仍先独立探测；
6. 恢复页进入豆包后重新核验 `用户867998`、工作任务、云电脑、Turbo高、目标技能；
7. 上传/发送/下载未知时先检查缩略图、官方提示和本地文件；证据不足不得重复。

连续恢复仍不能控制页面时，停止该网页依赖，继续可完成的本地台账、剧本、提示词和质检准备，不把控制慢误判为登录、额度、上传或生成失败。
